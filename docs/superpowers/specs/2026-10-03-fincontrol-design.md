# Финконтроль — дизайн

Дата: 2026-10-03

## Задача

Мобильное веб-приложение для учёта личных финансов. Одна HTML-страница,
без бэкенда, интерфейс на русском, тёмная тема, рассчитано на iPhone.
Устанавливается на экран «Домой» (PWA), работает офлайн, живёт на GitHub Pages.

## Решения

**Хранение.** `localStorage`, один ключ `fincontrol.v1` с JSON-состоянием.
Синхронный доступ, лимит ~5 МБ — десятки тысяч операций. Схема версионирована,
при чтении прогоняется через миграции. Экспорт/импорт JSON — защита от
«Очистить данные сайта».

**Балансы считаются пересчётом журнала, а не хранятся.** Состояние содержит
стартовые балансы и полный список операций; любой баланс выводится функцией от
них. Поэтому удаление и правка операции не могут рассогласовать балансы, а
история чистого капитала доступна для прогноза дат по целям.

**Кредитка — счёт с отрицательным балансом**, а не отдельное поле долга:

    баланс[счёт] = старт[счёт] + Σ(приходы) − Σ(расходы)
    старт[card]  = −стартовый долг

Трата с кредитки углубляет минус (долг растёт), перевод «банк → кредитка» его
сокращает. Чистый капитал = `cash + bank + card + непогашенные «мне должны»`.

**Публичность.** Репозиторий публичный (Pages на бесплатном аккаунте приватные
репозитории не обслуживает). Финансовые данные в репозиторий не попадают —
они в localStorage устройства. Дефолты в коде обезличены: стартовые балансы
нули, источники дохода «Смена» / «Выдача» / «Другое» (переименовываются в
настройках). Числовые лимиты оставлены рабочими: они анонимны, зато приложение
работает из коробки.

## Модель данных

    {
      v: 1,
      settings: {
        start:    { cash, bank, card },   // card — положительная сумма долга
        startDate,                        // дата отсчёта стартовых балансов
        minCash,                          // порог предупреждения, 20000
        weekLimit,                        // лимит «на себя» в неделю, 3200
        cardDueDay,                       // число месяца погашения, 29
        goals: [ ... ],                   // 100000 … 2500000
        sources: [ ... ],                 // источники дохода
        categories: [ ... ]               // категории трат
      },
      ops:   [ { id, type, date, amount, from?, to?, cat?, source?, note } ],
      debts: [ { id, who, amount, due, created, returned, returnedAt, opId } ]
    }

`type` ∈ `income` (есть `to`, `source`) | `expense` (есть `from`, `cat`) |
`transfer` (есть `from`, `to`). `date` — `YYYY-MM-DD`. Суммы — целые копейки
не нужны: храним рубли числом, ввод ограничен целыми рублями.

## Главный экран

- Чистый капитал крупно; плитки Наличные / Банк / Долг по кредитке / Мне должны
- Предупреждение, если наличных меньше `minCash`, с суммой нехватки
- Кредитка: долг и обратный отсчёт до `cardDueDay`. Число ежемесячное —
  после прохождения даты отсчёт переходит на следующий месяц; если в месяце
  меньше дней, дата схлопывается на последний день месяца. Нет долга — «долга нет»
- «На себя» за неделю: потрачено из `weekLimit`, остаток, полоса.
  Неделя начинается в понедельник 00:00 по местному времени
- Цели: полосы прогресса от чистого капитала. Темп = (капитал сейчас −
  капитал 28 дней назад) / 4 недели. Для каждой недостигнутой цели — прогноз
  даты. Истории меньше 7 дней → «нужно ещё N дней данных». Темп ≤ 0 →
  «прогноз недоступен»

## Ввод

Три кнопки: Доход / Трата / Перевод открывают нижний лист.

Ввод в два тапа обеспечивают **обучаемые чипы-комбо**: приложение выделяет из
истории три самых частых сочетания (категория + сумма + счёт) и показывает их
сверху листа; тап по чипу сохраняет операцию сразу. После сохранения внизу
на несколько секунд появляется «Добавлено · Отменить».

Ниже — полная форма: собственная цифровая клавиатура (системная на iOS зумит
страницу), чипы категорий и счетов, дата (по умолчанию сегодня), заметка.
Для переводов есть готовые кнопки «Наличные → Банк» и «Банк → Погасить кредитку».

«Мне должны»: кто, сколько, до какого числа. Кнопка «Вернул» спрашивает счёт
поступления и создаёт связанную операцию дохода.

## История

Сгруппирована по дням, новые сверху, фильтр по типу. Тап по строке открывает
лист с заполненными полями — правка или удаление.

## Экспорт / импорт

Экспорт тремя путями, потому что в standalone-режиме iOS скачивание бывает
недоступно: файл `fincontrol-YYYY-MM-DD.json`, системное «Поделиться»,
копирование JSON в буфер. Импорт — файл или вставка текста; структура
проверяется, замена подтверждается, прежнее состояние сохраняется снимком
для отмены.

## PWA

`manifest.webmanifest`, иконки PNG 180/192/512 (iOS требует PNG для
`apple-touch-icon`) — генерируются скриптом на Node через встроенный `zlib`,
без npm-зависимостей. `viewport-fit=cover` и отступы по safe-area.
Service worker: cache-first для оболочки, версионированное имя кеша, удаление
старых кешей при активации. Все пути относительные — на Pages приложение живёт
в подпапке.

## Проверка

Чистые функции расчётов лежат в блоке `CORE` внутри `index.html` между
маркерами и не обращаются к DOM. Тест читает файл, вырезает блок и исполняет
его через `node:vm`, затем проверяет: балансы и чистый капитал, правку и
удаление операции, границы недели, дату погашения (включая февраль для 29-го
числа), темп накоплений и прогноз, пустую историю, отрицательный темп,
валидацию импорта. Запуск: `node --test`.
